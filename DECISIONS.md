# Design Decisions

Append-only log: what was decided, why, what was rejected, and the constraint it creates. New entries go on top.
Reference an entry from code comments as `DECISIONS.md#YYYY-MM-DD-slug` when a choice looks odd out of context.

## 2026-08-25: Postgres identifiers are emitted lowercase *and* quoted
- Reason: Postgres folds unquoted identifiers to lowercase. Talk-to-data SQL written by Gemini is unpredictable about
  quoting (`Library_Branches` vs `"Library_Branches"` vs `library_branches`). Emitting `"library_branches"` makes all
  three spellings resolve (quoted lowercase == unquoted folded), while still allowing reserved words as names.
- The IR and CSV exports keep the original DDL spelling; only the database layer (and the prompt schema summary,
  F1.4) use lowercase. Two names differing only by case in one table → `DDLEmitError` (would collide).
- Rejected: preserving case with quotes (breaks unquoted LLM queries); unquoted emission (breaks reserved words).

## 2026-08-25: Pass-state gating is enforced mechanically by a `make check` marker
- Incident: while closing F1.1 the agent ran `make check | tail`, the pipe hid mypy's non-zero exit, and the feature
  was marked passing and committed with a red gate — exactly the "declared victory too early" failure (lecture 9).
- Fix at the verification layer (lecture 1 diagnostic loop), not by "trying harder": `make check` now touches
  `.harness/check.ok`; `scripts/features.py pass` refuses unless that marker is newer than every file under
  `src/ tests/ scripts/ Makefile pyproject.toml`. Gate commands are never piped in scripts (`set -euo pipefail`,
  or redirect to a log and test `$?`).
- Rejected: relying on the agent to read exit codes; a pre-commit hook (would block WIP commits mid-feature).

## 2026-08-25: Model = `gemini-2.5-flash` with thinking disabled by default
- Reason: the spec says "Gemini 2.0 Flash (or newer)"; `gemini-2.0-flash-001` returns 404 on the Vertex project
  (retired). `gemini-2.5-flash` is available, fast, and supports structured output, function calling and streaming.
- Verified: 2.5 models spend `max_output_tokens` on thinking → `.text` is `None` unless
  `ThinkingConfig(thinking_budget=0)` is passed. Default budget 0; configurable via `GEMINI_THINKING_BUDGET`.
- Rejected: `gemini-2.5-pro` as default (slower/costlier for bulk row generation; can be selected via `GEMINI_MODEL`).
- Constraint: the model id lives only in `config.py` (CLAUDE.md rule 2).

## 2026-08-25: Hybrid data generation — LLM for semantics/realism, deterministic engine for volume/integrity
- Reason: 1000 rows × 7 tables generated purely by LLM ≈ 7k rows ≈ 60+ calls, slow (measured ~2 rows/s), costly, and
  FK/unique integrity cannot be trusted to a model. Integrity is a code problem; realism is a language problem.
- Design: (1) LLM **planner** (structured output) reads the schema + user instructions and emits a per-column
  *recipe* (semantic type, generator strategy, ranges, enum weights, null ratio, date windows, dependencies);
  (2) LLM **value pools** for free-text/business-name columns (titles, descriptions, reviews…) requested in
  parallel batches; (3) a deterministic **expander** composes rows for any N honoring PK sequences, FK sampling in
  dependency order, uniqueness, NOT NULL, ENUM/CHECK, VARCHAR length, DECIMAL scale; (4) a **validator** proves it.
- A heuristic (offline) planner produces recipes from names/types when no LLM is available → the whole pipeline is
  unit-testable offline and degrades gracefully.
- Rejected: pure LLM row generation (speed/cost/integrity); pure Faker (unrealistic, ignores user instructions).

## 2026-08-25: Textual feedback is applied as a structured *EditPlan*, not by regenerating whole tables
- Reason: "make all salaries between 50k and 90k", "use Polish cities", "add 20 cancelled orders" are edits with
  different scopes. The LLM translates feedback into a typed plan (filter+set, regenerate column with new recipe,
  add/remove rows, rename pools) that the engine applies deterministically and revalidates (FK-cascade safe).
- Rejected: free-form "LLM rewrites the CSV" (breaks integrity, non-deterministic, expensive for 1000 rows).

## 2026-08-25: DDL parsing with sqlglot (MySQL dialect first, Postgres fallback) into our own IR
- Reason: sample DDLs are MySQL-flavoured (`AUTO_INCREMENT`, inline `ENUM`, `DATETIME`); sqlglot parses all three
  fully (verified). We keep our own pydantic IR (`schema/models.py`) so generation/validation/DDL emission do not
  depend on sqlglot internals, and so hand-written DDL variants can be normalised in one place.
- Rejected: regex parsing (fragile), sqlglot transpile to Postgres (emits invalid inline `ENUM (...)`).

## 2026-08-25: Postgres translation rules and per-dataset schemas
- `ENUM(...)` → `VARCHAR(n) CHECK (col IN (...))`; `AUTO_INCREMENT` → `GENERATED BY DEFAULT AS IDENTITY` (explicit ids
  are inserted, sequence reset after load); `DATETIME` → `TIMESTAMP`; `BOOLEAN`, `DECIMAL(p,s)`, `TEXT`, `DATE` kept.
- Each saved dataset is loaded into its own schema `ds_<dataset_id>` so several datasets coexist and "Talk to your
  data" picks one by setting `search_path`. FK constraints are added *after* bulk load (also handles cyclic FKs and
  doubles as an integrity proof).
- Rejected: Postgres native `CREATE TYPE ... AS ENUM` (namespacing/cleanup noise; CHECK is equivalent for this use).

## 2026-08-25: Text-to-SQL via function calling with a hard read-only guard
- Agent tools: `run_sql(sql)` and `render_chart(spec)`. Every SQL passes `storage/sql_guard.py`: sqlglot parse
  (postgres) → exactly one SELECT/UNION/CTE statement, no DML/DDL, auto `LIMIT` cap, executed in a `READ ONLY`
  transaction with `statement_timeout`. The chart is a *tool call* returning a typed spec → plotly, because Gemini
  disallows tools together with JSON response mode in one request.
- Manual function-calling loop (not AFC) so the UI can show SQL + result tables and stream the final answer.

## 2026-08-25: Observability = Langfuse v4 (OTel) + OpenInference google-genai instrumentor
- `openinference-instrumentation-google-genai` auto-captures every Gemini call as a GENERATION (model, usage);
  `@observe` spans name the pipelines (`data_generation`, `feedback_edit`, `talk_to_data_turn`);
  `propagate_attributes(session_id=<streamlit session>, tags=[...])`. `LANGFUSE_BASE_URL=https://cloud.langfuse.com`.
  Note: v4 has no `update_current_trace`; use `update_current_span` / `propagate_attributes`.
- Tracing is optional: without keys the app runs untraced (unit tests never need Langfuse).

## 2026-08-25: Harness structure follows the harness-engineering lectures
- CLAUDE.md ≤ 200 lines as a router; topic docs in `docs/`; `PROGRESS.md` for state; `docs/features.md` as the
  machine-readable feature list (WIP=1, pass-state gating with evidence); `DECISIONS.md` for rationale; Makefile as
  the single command surface; executable architecture rules (`make arch-check`); session exit gate (`make exit-check`);
  independent fresh-context verifier for milestone gates (generator/evaluator separation).
- Python 3.14 kept from the scaffold (all dependencies import fine); `uv` for env/lock; ruff + mypy for L1 checks.
